В качестве практического задания для закрепления синтаксиса работы с методами типов, напишем реализацию простого калькулятора, который умеет выполнять четыре арифметических действия: сложение, вычитание, умножение и деление.

Итоговый тип должен иметь примерно такой интерфейс:

```rust
fn main() {
    let res = Calc::default().add(2).add(2);
    println!("{res}");
}
```

Данный пример вычисляет результат `2 + 2` и выводит:
`Результат: 4`

Пусть наш калькулятор будет совсем прост и иметь лишь один "основной" регистр:

```rust
struct Calc {
    r0: i32,
}
```

Для инициализации такой структуры можно использовать самый простой синтаксис, когда каждому полю устанавливается значение:

```rust
let calc = Calc { r0: 42 };
```

Если полей много, часть из них необязательные или если нужно делать еще какую-то работу для корректной инициализации, можно написать "конструктор", который по традиции называется `new()`. Он может иметь или не иметь аргументов. В нашей ситуации мы могли бы передавать в `new()` начальное значение регистра, но скорее всего, для пользователя API логичнее, когда калькулятор при инициализации имеет значение регистра установленное в 0:

```rust
impl Calc {
  fn new() -> Self {
    Self { r0 : 0 }
  }
}
```

Такой конструктор можно сгенерировать и используя уже встроенный в Rust механизм `derive`:

```rust
#[derive(Default)]
struct Calc {
    r0: i32,
}
```

Так как встроенный тип `i32` [реализует (искать `impl Default for i32`)](https://doc.rust-lang.org/std/primitive.i32.html) характеристику [`Default`](https://doc.rust-lang.org/std/default/trait.Default.html), то `derive` сработает и у `Calc` появится новый метод: `Calc::default()`. Реализация `Default` для `i32` производит значение `0`.

Вы так же можете использовать tuple-синтаксис для определения структур с безымянными полями. Это может сделать код короче, особенно когда имя поля не несет смысла или когда тип существует только ради того, чтобы "обернуть" другой тип (этот паттерн в Rust называется Newtype):

```rust
struct Calc(i32);
```

Такую структуру можно инициализировать синтаксисом, похожим на ручное написание метода `new()`:

```rust
let calc = Calc(0);
```

## Реализация цепочки вызовов

Чтобы методы `Calc` можно было удобно вызывать по цепочке, они должны принимать владение и отдавать его. Например, реализация `add()`:

```rust
fn add(mut self, rhs: i32) -> Self {
	self.r0 += rhs;
	self
}
```

Здесь мы принимаем во владение `Calc` (его значение называется `self`), изменяем его поле и возвращаем. Так как почти все в Rust является выражением и результатом блока считается результат последнего выражения, нам не нужно писать `return` в последней строчке и ставить `;`.
Другими словами, последняя строчка может быть также написана как `return self;`

Реализуйте остальные арифметические операции самостоятельно.

## Отображение результата

Если вы сейчас попробуете собрать программу, то строчка `println!("{res}");` приведет к ошибке

```
error[E0277]: `Calc` doesn't implement `std::fmt::Display`
```

Это потому что наш тип пока мало что умеет, из характеристик мы реализовали только `Default`.

> К сожалению, в Rust сложно понять какие характеристики реализует тип. rust-analyzer этого не умеет. Кажется, только intellij-rust [хорошо это показывает](https://github.com/rust-lang/rust-analyzer/issues/14661).
> Есть надежный, но не очень удобный способ: сгенерировать документацию `cargo doc --open`.
> После ее открытия в браузере, нужно перейти на страницу структуры `Calc`. В разделах Trait Implementations, Auto Trait Implementations и Blanket Implementations будут перечислены все характеристики.
> Обратите внимание, что для нашего типа автоматически выведены маркерные характеристики: `Send`, `Sync`, `Unpin`. Мы вернемся к ним в будущем.

`Display` реализовывается для типов, которые должны иметь осмысленное текстовое представление для пользователя. Так как нельзя заранее знать, что хочет пользователь, `Display` нельзя вывести с помощью механизма `derive`. Для реализации характеристики необходимо начать новый блок имплементаций и указать к какой характеристике он относится:

```rust
impl std::fmt::Display for Calc {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "Результат: {}", self.r0)
    }
}
```

Теперь программа соберется.
Реализация `Display` автоматически добавляет и реализацию `ToString`, которая предоставляет один единственный метод `to_string()`, который, как следует из названия, превращает значение в `String`.
Это удобно, ведь следующий код эквивалентен, но вариант с `to_string()` короче и выразительнее:

```rust
let calc = Calc::default();
let string_format = format!("{calc}");
let to_string = calc.to_string();
assert_eq!(string_format, to_string);
```

## Обработка ошибок

К сожалению, даже при реализации такого простого калькулятора, мы сталкиваемся с несколькими видами ошибок:

- Целочисленное переполнение
- Деление на ноль

Попробуйте, например, запустить подобный код: `Calc::default().div(0);`
Программа упадет с паникой:

```
thread 'main' panicked at src/main.rs:15:9:
attempt to divide by zero
```

Мы пишем на Rust, чтобы создавать надежные программы, желательно с максимальными гарантиями. Падение в случайном месте с паникой не является ожидаемым поведением. Поэтому, хорошая программа на Rust никогда не должна падать с паникой. Подробнее [в книге](https://doc.rust-lang.ru/book/ch09-03-to-panic-or-not-to-panic.html).

Для реализации логики значение/ошибка в Rust есть два специальных типа - `Option` и `Result`. `Option` может или содержать значение (тогда оно равно варианту `Some`) или не содержать - вариант `None`. С синтаксисом и примерами использования можно познакомиться [здесь](https://doc.rust-lang.ru/stable/rust-by-example/error/option_unwrap.html).

Для этой задачки вам будет очень полезен метод `Option::map()`, который производит указанную операцию над значением или не делает ничего, если значения нет. К примеру, метод `add()` мог бы выглядеть так:

```rust
fn add(mut self, rhs: i32) -> Self {
	self.r0 = self.r0.map(|r| r + rhs);
	self
}
```

Заметьте, что если вы измените тип `r0` на `Option<i32>`, то реализация `Default` для `Option` будет устанавливать его в значение `None`. Похоже, `#[derive(Default)]` придется убрать и все же написать конструктор (или имплементацию `Default`, как мы это делали с `Display`) вручную, например:

```rust
impl Default for Calc {
    fn default() -> Self {
        Self { r0: Some(0) }
    }
}
```

### Переполнение

При компиляции в профиле отладки (простой запуск `cargo run`) к арифметическим операциям будет добавлена проверка на переполнение. Но в релизе такие проверки могут отрицательно повлиять на производительность, поэтому они исключаются. Переполнение не приводит к неопределенному поведению, а результат специфицирован - происходит переход через максимальное (или минимальное) значение. `255u8 + 1` становится `0` и так далее.
Чтобы вставить проверку, нужно пользоваться методами `wrapping_*`, `checked_*` и`saturating_*`, определенными для числовых типов.

## Тест

Задание будет считаться пройденным, если следующий тест проходит (добавьте текст ниже в конец `main.rs`):

```rust
#[cfg(test)]
mod test {
    use crate::Calc;

    #[test]
    fn simple_addition() {
        let res = Calc::default().add(2).add(2);
        assert_eq!("Результат: 4", res.to_string());
    }

    #[test]
    fn overflow() {
        let res = Calc::default().add(i32::MAX).add(1);
        assert_eq!("Ошибка", res.to_string());
    }

    #[test]
    fn division_by_zero() {
        let res = Calc::default().div(0);
        assert_eq!("Ошибка", res.to_string());
    }
}

```

Запустить тесты можно командой: `cargo test`

## Задачи со звездочкой

1. Мы не различаем ошибку, в случае переполнения и деления на ноль. Можно использовать `Result`, чтобы специфицировать тип ошибки или хранить ее в другом поле.
2. Мы не можем использовать перегруженные операторы `+ - / *`, то есть нельзя просто написать что-то вроде `let res = Calc(2) + Calc(2)`;
   Они так же реализованы через характеристики и их поддержка реализуется аналогично тому, как мы это делали для `Display` и `Default`. Подробнее: https://doc.rust-lang.org/std/ops/
