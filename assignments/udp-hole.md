В этом задании мы реализуем [**UDP hole punching**](https://en.wikipedia.org/wiki/UDP_hole_punching) – технику, позволяющую установить прямое соединение между двумя устройствами, находящимися за NAT. Это особенно полезно для P2P-сетей, онлайн-игр и VoIP.

Мы будем использовать **UDP** [(User Datagram Protocol)](https://en.wikipedia.org/wiki/User_Datagram_Protocol), так как в отличие от TCP, он не требует установки соединения и позволяет отправлять пакеты напрямую. Однако NAT (Network Address Translation) мешает этому, скрывая локальные IP-адреса.

Часто интернет ассоциируют только с веб-технологиями, но на самом деле это сеть, надстроенная над более низкоуровневыми протоколами, такими как UDP.

Это задание интереснее выполнять в паре и лучше всего, если вы находитесь в разных сетях. Раздаваемый мобильный интернет через Wi-Fi не всегда работал у меня, так что рекомендую тестировать, используя домашний Wi-Fi или подобную "фиксированную" сеть.

## Цель

Создать клиент, который:

- **Регистрируется** на сервере, сообщая свой внешний IP и порт через UDP.
- **Получает** адрес пира через HTTP-запрос.
- **Устанавливает** прямое UDP-соединение, обходя NAT.
- **Обменивается** текстовыми сообщениями.

> **Важно:** Сервер уже реализован, вам нужно написать только клиент.

### Почему это проблема

В IPv4 давно не хватает IP-адресов, поэтому для экономии пространства используется NAT – механизм трансляции локальных адресов в глобальный. Это удобно для маршрутизации, но создаёт проблему: устройства за NAT **не могут принимать входящие соединения**, так как их локальный IP недоступен извне.

Однако если **оба клиента отправят UDP-пакеты одновременно**, NAT создаст "пробитый" маршрут, через который данные смогут передаваться напрямую.

В IPv6 у каждого хоста есть [белый адрес](https://selectel.ru/blog/white-and-grey-ip/), поэтому NAT чаще всего не требуется.

## Сервер

На сервере уже запущен рандеву-сервис, который:

1. **Принимает UDP-регистрацию** (клиент отправляет имя, сервер фиксирует его внешний IP и порт).
2. **Отвечает на HTTP-запросы** (`/wait/{peer}`) другим клиентам, передавая им последний известный IP-адрес пира.

Адрес сервера:

- **HTTP API:** `http://45.151.30.139:8080/api`
- **Swagger UI**: http://45.151.30.139:8080/help
- **UDP:** `45.151.30.139:4200`

Рандеву-сервер используется только для установления соединения. После обмена адресами весь трафик идёт напрямую по UDP.

### UDP-регистрация

Перед установкой соединения клиент должен сообщить серверу свой внешний IP-адрес и порт. Это делается с помощью UDP-пакета регистрации. Пакет можно отправить, используя метод [`send_to()`](https://doc.rust-lang.org/std/net/struct.UdpSocket.html#method.send_to) у `UdpSocket`.

Пакет имеет такой формат:

| Поле         |   Значение   | Длина  |
| :----------- | :----------: | :----: |
| Заголовок    |     0x00     | 1 байт |
| Имя клиента  | UTF-8 строка | N байт |
| Конец пакета |     0xFF     | 1 байт |

Пример пакета для клиента с именем `"alexander"`:

```rust
[0x00, 0x61, 0x6c, 0x65, 0x78, 0x61, 0x6e, 0x64, 0x65, 0x72, 0xFF]
```

(где `0x61 0x6c 0x65 ...` — это байтовое представление строки `"alexander"` в UTF-8)

После получения пакета сервер запоминает IP-адрес и порт отправителя.
### Алгоритм работы сервера

Сервер запоминает адрес клиента при его регистрации по UDP. Если в этот момент другой клиент уже ожидает его через HTTP (`/wait/{hostname}`), он сразу получает адрес. Иначе данные хранятся до следующего запроса

**HTTP запрос:**

- **GET /wait/{hostname}?timeout=…** – ожидает появления нового обновления для клиента. Если обновление уже имеется, оно возвращается мгновенно.

HTTP-запрос можно сделать методом [`get()`](https://docs.rs/reqwest/latest/reqwest/struct.Client.html#method.get) у `reqwest::Client()`. 

## Обобщенный пример

```rust
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let cli = Cli::parse();

    // Регистрируемся и получаем UDPSocket для использования в будущем
    let socket = register(&cli.rendezvous, &cli.name)?;

    // Запрашиваем адрес пира через HTTP
    let peer = get_peer_address(&cli.rendezvous, &cli.peer).await?;

    // Отправляем пробивающий пакет
    socket.send_to(&[0], peer)?;

    let stdin = io::stdin();
    loop {
        if cli.client {
            let mut input = String::new();
            stdin.read_line(&mut input)?;
            let input = input.trim();
            socket.send_to(input.as_bytes(), peer)?;
        } else {
            let mut buf = [0; 1024];
            let len = socket.recv(&mut buf)?;
            println!("{}", std::str::from_utf8(&buf[..len])?);
        }
    }
}
```
